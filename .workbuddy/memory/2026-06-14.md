## 第二轮复核修复（2026-06-14 上午）

### 复核未通过问题逐项修复

1. **增量索引真正事务回滚**
   - `indexFiles()` 现在返回 `IndexUpdateResult`
   - 每个文件更新前：`retrievePoints()` 备份旧 Qdrant points（含 vector + payload）；`lexicalIndexService.findByDocumentId()` 备份 Lucene；保存 previous manifest record
   - 失败时：`rollbackPerFileTransaction()` 依次恢复 manifest → Lucene → Qdrant（re-upsert 旧 points）
   - 新增 `PerFileTransaction` 内部类跟踪每个文件的提交状态

2. **删除事务三阶段回滚**
   - `deleteDocumentByPathLocked()`：先备份三方 → 执行删除 → 失败时 `rollbackDelete()` 恢复
   - Qdrant 恢复使用 `retrievedPointToPointStruct()` 将旧 point 重新 upsert

3. **modified/index version 逻辑**
   - `indexFiles()` 返回结构化 `IndexUpdateResult`（`modified`, `consistent`, `errors`）
   - 成功修改 → `modified=true` → bump version
   - 未变化 → `modified=false`
   - 失败且回滚成功 → `modified=false`
   - 部分回滚失败 → `consistent=false`，manifest 记录错误

4. **stable doc ID 与 Python 兼容**
   - `stableFileDocId()` 基准改为 `projectRoot`（自动检测：配置 → 类路径 → user.dir）
   - 生成 `file:data/ukm_ftsm/filename.txt`，与 Python `stable_file_doc_id()` 逐字一致
   - 测试覆盖：普通文件、子目录、Windows 路径分隔符、不同 cwd、Tauri 绝对路径、UUIDv5 chunk ID

5. **reconcileMissingFiles 调用**
   - 新增公共入口 `syncMissingFiles()`，明确提供"同步磁盘已删除文件"语义
   - 内部使用 `transactionalDeleteSingleDocument()` 统一删除事务

6. **source_type 强制四类存在**
   - 改为 `REQUIRED_SEED_DOCUMENTS = {"ftsm_official_website.txt"}`
   - source_type 分布只做日志统计，不作为硬失败条件

7. **查询不应创建 legacy collection**
   - `getClient()` 只连接，不创建 collection
   - `createCollectionWithProbedDimension()` 仅用于 full rebuild 显式创建 staging

8. **混合检索超时**
   - `safeGet()` 使用 `get(timeoutMillis, TimeUnit.MILLISECONDS)`
   - 超时后 `future.cancel(true)`
   - 线程池：有界队列（100）+ CallerRunsPolicy

9. **完整索引验证（ID 集合）**
   - `validateRebuiltIndex()` 收集三方 ID 集合，验证 `Set` 相等性
   - 同时验证 dimension、required seed、无重复 ID

10. **运行时文件污染**
    - `.gitignore` 补充 `.qdrant-initialized`、`storage/`、`lucene_local/`、`qdrant_local/app.err`
